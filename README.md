# SmashPang Multi-Group

โคลนจาก SmashPang (ระบบจัดการก๊วนแบดมินตัน & POS) เพิ่มการ **แยกก๊วน** — หลายก๊วนใช้ระบบเดียวกันได้ ข้อมูลแยกกันหมด

## ก๊วนทำงานแยกกันอย่างไร
- แต่ละก๊วนมี **รหัสก๊วน** (เช่น `tue-club`), ชื่อ และ **PIN** ของตัวเอง เจ้าของก๊วนสร้างได้จากหน้าแรก (`/`) หลังสมัครสมาชิก
- เข้าก๊วนผ่านลิงก์ `/?g=<รหัสก๊วน>` · จอคิวสาธารณะ `/?g=<รหัสก๊วน>&queue`
- ทุกตารางใน DB มี `group_id`; API ทั้งหมดอยู่ใต้ `/api/g/:gid/...`
- PIN ถูกตรวจที่ backend (แฮช scrypt) แล้วออก token ที่ผูกกับก๊วนนั้นเท่านั้น — token ก๊วน A เรียก API ก๊วน B ไม่ได้
- ล็อกอินผิดเกิน 8 ครั้ง/10 นาที (ต่อ IP+ก๊วน) จะโดนบล็อกชั่วคราว
- ส่วนที่เหลือ (จัดคอร์ด, Auto Match, POS, การเงิน, ประวัติ) เหมือนระบบเดิม

## หลักการทำงาน
1. **เข้าก๊วน**: ใส่รหัสก๊วน → กรอก PIN (เจ้าของก๊วนที่ล็อกอินอยู่เข้าได้เลยไม่ต้องใช้ PIN)
2. **เลือกรูปแบบก๊วน**: เข้ามาแล้วระบบให้ผู้จัดเลือกเองทุกวัน เปิดให้ครบ 4 โหมด — คิดตามเกม (ส้ม) · บุฟเฟต์ (เขียว) · หารเท่า (ฟ้าน้ำทะเล) · ตีเฮฮา (ม่วง) สีหลักของทั้งแอปเปลี่ยนตามโหมด กด "จบวัน" แล้ววันถัดไปเลือกใหม่ได้
3. **สมัครสมาชิก (เจ้าของก๊วน)**: อีเมล + Username + รหัสผ่าน (อย่างน้อย 6 ตัว) ใช้งานได้ทันที ไม่ต้องยืนยันอีเมล · ล็อกอินด้วย Username หรืออีเมล + รหัสผ่าน แล้วสร้างก๊วนได้ (รหัสก๊วน + PIN) · ชื่อก๊วนตั้งในระบบตอนเข้าครั้งแรก
4. **ดูย้อนหลัง**: แท็บ สถิติ → กรองตามโหมด และเลือกวันที่ (แยกกลุ่มตามโหมด)
5. **แอดมินระบบ**: ตั้ง `ADMIN_EMAIL` (Gmail) ใน `.env` แล้วสมัครด้วยอีเมลนั้น (สมัครบัญชีนี้เป็นคนแรกทันทีหลังติดตั้ง เพราะไม่มีการยืนยันอีเมล) → เข้า `/?admin` ดูผู้ใช้/ก๊วนทั้งหมด ระงับ-ปลดระงับ ยืนยันให้ด้วยมือ เปลี่ยนชื่อ/PIN ลบก๊วน
- ไม่มีการส่งอีเมลแล้ว จึงไม่ต้องตั้ง `SMTP_*` (ตัวแปรเหล่านี้ไม่มีผล) และยังไม่มีระบบลืมรหัสผ่านทางอีเมล
- ก๊วนที่สร้างไว้ก่อนมีระบบบัญชีไม่มีเจ้าของ (แอดมินจัดการได้) และยังเข้าด้วยรหัสก๊วน+PIN
- ออกแบบหน้าจอสำหรับ Desktop และ iPad เป็นหลัก

## รันในเครื่อง
```bash
cp .env.example .env        # แก้ค่า DB_* ให้ตรง; ถ้าใช้ docker-compose ด้านล่าง ใช้ DB_PORT=3307
docker compose up -d db     # MySQL สำหรับ dev
npm install
npm run dev                 # backend :3001 + vite :3000
```
Production: `npm run build` แล้ว `npm start` (backend เสิร์ฟ `dist/` ให้)

## ตัวแปร .env สำคัญ
| ตัวแปร | ความหมาย |
|---|---|
| `DB_*` | MySQL — ต้องเป็นฐานข้อมูลใหม่ (schema ต่างจากระบบเดิม) ตารางสร้างอัตโนมัติตอน boot |
| `TOKEN_SECRET` | คีย์เซ็น token ล็อกอิน (ตั้งให้คงที่ไม่งั้นต้อง login ใหม่ทุกครั้งที่ restart) |
| `ADMIN_EMAIL` `APP_URL` `SMTP_*` | บัญชีเจ้าของก๊วน/แอดมิน ดู `.env.example` |
| `CORS_ORIGIN` | origin ที่อนุญาต คั่นด้วย `,` |

## หมายเหตุ
- ไม่ได้ย้ายข้อมูลจากระบบเดิม — ก๊วนใหม่เริ่มจากว่าง
- ไม่มีบัญชีผู้ใช้: ใครรู้รหัสก๊วน+PIN ก็เข้าได้ (ผู้ดูแลก๊วนเดียวต่อ PIN)
